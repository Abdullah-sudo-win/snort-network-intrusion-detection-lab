# Snort Alert Analysis Report

## 1. Report Overview

**Project:** Snort Network Intrusion Detection Lab  
**Platform:** TryHackMe  
**Tool:** Snort 2  
**Analysis Type:** Network Traffic Monitoring and Rule-Based Detection

### Objective

The objective of this report is to document my analysis of two custom Snort detection rules created during my TryHackMe lab.

The rules focus on ICMP traffic monitoring and TCP traffic directed to destination port 80.

This report explains their detection logic, observed PCAP test results, and limitations.

## 2. Detection Rule 1 – ICMP Traffic

### Rule

```snort
alert icmp any any -> any any (msg:"ICMP Packet Found"; sid:1000001; rev:1;)
```

### Detection Logic

This rule monitors ICMP traffic regardless of source and destination IP addresses.

When matching ICMP traffic is detected, Snort generates an alert with the message `ICMP Packet Found`.

### Analyst Interpretation

ICMP is commonly used for network diagnostics and communication, including ping requests and replies.

An ICMP alert does not automatically indicate malicious activity.

A SOC analyst should consider the ICMP message type, source and destination addresses, frequency, and network context before determining whether further investigation is necessary.

## 3. Detection Rule 2 – TCP Traffic to Port 80

### Rule

```snort
alert tcp any any -> any 80 (msg:"HTTP Traffic Detected"; sid:1000002; rev:1;)
```

### Detection Logic

This rule monitors TCP traffic directed to destination port 80.

When traffic matches the rule, Snort generates the following alert: `HTTP Traffic Detected`.

### Analyst Interpretation

TCP port 80 is commonly associated with HTTP communication.

However, this rule identifies traffic based on its destination port. It does not inspect the application payload or independently verify HTTP content.

A more detailed investigation would require examining the network traffic and application-layer information.

## 4. PCAP Validation – Observed Results

I replayed two provided TryHackMe PCAP files through Snort 2 using the `-r` option and console alert output.

### ICMP test

**Input file:** `icmp-test.pcap`

**Command used:**

```bash
sudo snort -c /etc/snort/snort.conf -q -r icmp-test.pcap -A console -n 10
```

**Observed result:**

- Snort displayed alerts generated by the custom rule with SID `1000001`.
- Alert message: `ICMP Packet Found`.
- The output also included built-in ICMP alerts, including ICMP PING and ICMP Echo Reply.
- The displayed traffic included ICMP packets in both directions between `192.168.175.129` and `172.67.27.10`.

**Validation:** The custom ICMP rule matched ICMP packets in the PCAP and generated alerts.

### TCP destination port 80 test

**Input file:** `http2.pcap`

**Command used:**

```bash
sudo snort -c /etc/snort/snort.conf -q -r http2.pcap -A console
```

**Observed result:**

- Snort displayed repeated alerts generated by the custom rule with SID `1000002`.
- Alert message: `HTTP Traffic Detected`.
- The displayed TCP flow was from `10.67.68.41:49892` to `10.67.155.254:80`.

**Validation:** The custom TCP rule matched packets with destination port 80 and generated alerts. This confirms the port-based rule behavior; it does not independently prove that the payload was valid HTTP.

### Validation summary

| Test | PCAP file | Custom SID | Observed outcome |
|---|---|---|---|
| ICMP | `icmp-test.pcap` | 1000001 | Matching alerts displayed |
| TCP destination port 80 | `http2.pcap` | 1000002 | Matching alerts displayed |

## 5. Detection Comparison

| Attribute | ICMP Rule | TCP Port 80 Rule |
|---|---|---|
| SID | 1000001 | 1000002 |
| Protocol | ICMP | TCP |
| Destination port | Not applicable | 80 |
| Alert message | ICMP Packet Found | HTTP Traffic Detected |
| Detection method | Protocol-based | Protocol and port-based |

## 6. Investigation Considerations

During a real SOC investigation, I would consider:

- Source IP address
- Destination IP address
- Protocol
- Source and destination ports, when applicable
- Timestamp
- ICMP message type, when applicable
- Frequency of matching traffic
- Relevant network and application context

## 7. Detection Limitations

- The ICMP rule does not filter specific ICMP message types.
- The TCP rule only matches destination port 80.
- The TCP rule does not inspect HTTP payload contents.
- HTTPS traffic on port 443 is not covered by the TCP port 80 rule.
- A matching alert does not automatically establish malicious activity.
- The PCAP tests were performed against selected lab files and do not establish detection performance across all network traffic.
